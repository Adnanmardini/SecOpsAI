

## Individual Lessons Learned

The most significant lesson I took from this project was that **environment stability is a prerequisite for productivity, not an afterthought**. Early in the pipeline development phase, I lost a substantial amount of time attempting to get the full Docker stack running on a local WSL2 environment on an HP laptop. The combination of WSL2 networking quirks, Docker Desktop resource constraints, and Kafka's dependency on stable hostname resolution created a cascade of issues that were difficult to isolate. The breakthrough came when I pivoted entirely to GitHub Codespaces as the working environment — within a single session, the same `docker compose up` command that had been failing locally ran without modification and the 50,000-record Kafka-to-PostgreSQL stress test completed successfully with zero data loss. This experience taught me to treat environment reproducibility as a first-class engineering concern from day one: if a stack cannot spin up cleanly on a fresh cloud environment, it is not truly portable, and debugging locally introduces variables that obscure the real problem. Going forward, I would advocate for the team to establish a canonical Codespaces or cloud dev environment at the start of any infrastructure-heavy project, so that every team member is working against the same baseline and environment-specific failures do not block pipeline progress during time-sensitive cohort sprints.
